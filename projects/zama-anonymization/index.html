01 Comment ça marcheHow it works

Le modèle d'anonymisation tourne sur le serveur, mais sur des chiffrés. Le client garde la clé secrète ; le serveur ne reçoit que des octets aléatoires et renvoie un résultat lui aussi chiffré. The anonymization model runs on the server, but over ciphertexts. The client keeps the secret key; the server only ever sees random-looking bytes and returns an equally encrypted result.

04 Le FHE en brefFHE in a nutshell

🧮 Calculer sans déchiffrerCompute without decrypting

Le chiffrement totalement homomorphe permet d'effectuer additions et multiplications directement sur les chiffrés. Enc(a) ⊕ Enc(b) = Enc(a+b). Le serveur calcule un résultat correct sans jamais accéder aux valeurs.Fully Homomorphic Encryption lets you run additions and multiplications directly on ciphertexts. Enc(a) ⊕ Enc(b) = Enc(a+b). The server computes a correct result without ever accessing the values.

🤖 Un classifieur, en FHEA classifier, in FHE

Chaque mot est transformé en vecteur (embedding), puis une régression logistique compilée avec Concrete ML prédit son type d'entité (personne, lieu, organisation…). Le tout s'exécute sur les chiffrés.Each word becomes a vector (embedding), then a logistic regression compiled with Concrete ML predicts its entity type (person, location, organization…). All of it runs over ciphertexts.

🔑 Le client garde le contrôleThe client stays in control

La clé secrète ne quitte jamais le navigateur. Le serveur reçoit la clé d'évaluation (qui ne déchiffre rien) et les chiffrés. Seul le client peut lire le résultat.The secret key never leaves the browser. The server gets the evaluation key (which decrypts nothing) and the ciphertexts. Only the client can read the result.

💬 Pourquoi anonymiser ?Why anonymize?

Pour profiter d'un LLM dans le cloud sans lui confier vos noms, emails ou numéros. On masque les PII côté chiffré, on envoie le texte neutralisé au LLM, puis on restaure les vraies valeurs en local.To use a cloud LLM without handing it your names, emails or numbers. PII is masked on the encrypted side, the neutralized text goes to the LLM, then the real values are restored locally.

05 QuestionsFAQ
En quoi est-ce différent du démo Hugging Face ?How does this differ from the Hugging Face demo?

Le démo Zama exécute un vrai pipeline FHE côté serveur (génération de clés, chiffrement, inférence Concrete ML, déchiffrement) sur des embeddings de mots. Ici, l'hébergement statique impose une simulation : la détection d'entités tourne dans le navigateur via des règles et dictionnaires, mais l'interface et l'enchaînement des étapes reproduisent l'expérience originale.The Zama demo runs a real server-side FHE pipeline (keygen, encryption, Concrete ML inference, decryption) over word embeddings. Here, static hosting forces a simulation: entity detection runs in the browser via rules and dictionaries, but the UI and step sequence reproduce the original experience.

La détection d'entités est-elle parfaite ?Is the entity detection perfect?

Non — c'est une heuristique légère (regex pour emails/téléphones/IBAN/dates/montants + dictionnaires de noms, lieux et organisations + détection des séquences capitalisées). Comme tout système de reconnaissance d'entités, il peut manquer ou sur-détecter. Le vrai modèle Zama, entraîné, est nettement plus robuste.No — it's a lightweight heuristic (regex for emails/phones/IBAN/dates/amounts + name, place and organization dictionaries + capitalized-sequence detection). Like any NER system it can miss or over-detect. Zama's trained model is far more robust.

Le FHE est-il vraiment sûr ?Is FHE really secure?

Le FHE repose sur le problème Learning With Errors (LWE), réputé résistant même aux ordinateurs quantiques. Tant que la clé secrète reste côté client, le serveur ne voit que du bruit. Le coût : le calcul sur chiffrés est plus lent qu'en clair, d'où l'intérêt de modèles compacts comme la régression logistique.FHE is based on the Learning With Errors (LWE) problem, believed to resist even quantum computers. As long as the secret key stays client-side, the server only sees noise. The trade-off: computing on ciphertexts is slower than in the clear, hence the use of compact models like logistic regression.
